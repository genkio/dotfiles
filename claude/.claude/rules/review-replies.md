When drafting PR review replies, do not explain the code changes. Name the commit, then give only what the diff cannot show: the reason for a deviation from the suggestion, or the evidence for a comment needing no change. Keep each reply to one to three short sentences.

Label each draft with the comment's anchor id (`r<id>`), not a file and line. Put each reply body in a fenced `markdown` code block so the raw Markdown survives copy and paste.
