make, split into phases

scripts/opinionated-flow.sh --phase <name>, repeatable and required. The Makefile is a thin wrapper: each target is one or more --phase flags into a single process, so the password is asked for once.

A bare make opens a checkbox list of the phases instead of running anything. All five start ticked, so Enter is the old meaning of make.

What left Homebrew, and why

Homebrew moved Intel macOS to Tier 3, stopped building x86_64 bottles, and plans to drop Intel entirely in September 2027 or later (Support Tiers). It does fall back to a bottle built for an older macOS of the same arch, so an Intel Mac on Sonoma or newer still gets whatever was bottled before the cutoff. Below Sonoma, effectively everything compiles.

Each of the first three ships an official prebuilt x86_64 binary that the formula would have thrown away and rebuilt. PI_SKIP_VERSION_CHECK=1 moved from the formula's wrapper into zsh/.zshrc, because mise now owns pi's version and a pi update would install a second copy beside it. Machines built before this change keep their Homebrew copies until you brew uninstall them; ~/.local/bin and mise's shims come first on PATH, so the new ones win in the meantime.

Tailscale stays a formula, and that is deliberate. The tailscale-app cask is tidier on every axis — no root LaunchDaemon, no stale daemon after an upgrade, no root-owned kegs, and no need for scripts/tailscale-exit.sh, which exists only because the formula's darwin router never programs the v4 default route. It is still the wrong choice here: Tailscale SSH's server component runs only on Linux and the open-source tailscaled, and this machine has to accept inbound Tailscale SSH. So the formula and its three helper scripts stay. The Go build on Intel is the price, and together with the root daemon it is why make tailscale owns the install rather than any phase: a bootstrap should not put a machine on a tailnet unasked.

Where it landed. rust and llvm are gone from the flow entirely, and the phases no longer compile Go at all: gh, lazygit and lazysql were the last three, and all three are downloaded release binaries now. go survives as a mise toolchain in config.toml, and the only Go build left in the repo is make tailscale's. On an Intel Mac, make core now compiles exactly one thing: tmux, plus the tiny pkgconf it builds against. Everything else in core is a bottle or a downloaded release binary.

And who upgrades them now. brew upgrade is what kept all of these current while they were formulae, so make update had to take that job over or they would simply have stopped moving. The mise config is split so the answer is a file boundary: everything in conf.d/ is tracked to latest (the five aqua: CLIs from core, plus gh, pi, lazygit, lazysql, ctx7 and @playwright/cli from dev), and config.toml is frozen (node, python, go, uv, the typescript pair), where a global bump buys nothing. update.sh never passes --bump, and mise upgrade honours each entry's range, so the deliberate @playwright/cli pin sits safely inside an auto-upgraded file.

The rule, for when the line drifts. Homebrew will keep rebuilding formulae, and each rebuild drops another stale Sonoma x86_64 bottle. A tool stays in Brewfile.base while Homebrew is still right for it: bottled on both arches, or a small C build with bottled deps. Lose the bottle and have an aqua entry → the conf.d file for the phase that already installs it (cli.toml for core, dev.toml for dev), so the move never changes which machines get the tool. Lose the bottle with no prebuilt binary anywhere → whichever opt-in target wants it, never Brewfile.base. tmux is the current example of the first case; mole was the example of the last and got dropped instead, because nothing here ever invoked it.

Invariants the split encodes

  • Flag order does not set run order. --phase dev --phase macos still runs macos first. The sequence is hardcoded in the script because touchid genuinely must be last.
  • The script installs nothing to bootstrap itself. It does not clone the repo and does not install the CLT, because the checkout is a precondition and the CLT came with the git that made it. Those two branches could never fire.
  • macos has no Homebrew dependency. That is the point of it: brew arrives in core.
  • apps and dev hard-fail early via require_brew instead of dying mid-bundle.
  • A phase is a category of software, not a unit of waiting — and that is a reversal. heavy existed on the opposite principle: a video player, a codec library and a VPN client grouped by nothing but how long an Intel Mac spent compiling them. Once IINA replaced mpv on Intel, that group was no longer the longest wait (core is), so the grouping had no reason left. Each piece went where it belongs, and tailscale went to its own target because it starts a root daemon.
  • Re-runs are cheap. brew bundle check short-circuits satisfied bundles, the pinned installers compare versions first, and stow steps step aside rather than clobbering a real file.
  • One password, one process. That is the only reason make all passes five flags instead of chaining five targets.
