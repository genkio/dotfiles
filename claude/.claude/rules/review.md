Code review: default to the subagent-review skill for any review of a branch/diff/PR - including bare "review this" asks and /code-review-style requests. It fans out read-only `review-lens` subagents (pinned to sonnet, Read/Grep/Glob only), so nothing runs on the session's model. Never invoke the built-in /code-review; its finders inherit the calling session's model and usage limits.

herd-review is the cross-model panel: a non-Claude family as full reviewers in tmux panes ALONGSIDE subagent-review's lenses, with model-tagged findings and a cross-family rebuttal round. Spawn them with `herdlet spawn --agent pi --sandbox read-only`: Codex `--model openai-codex/gpt-5.6-sol --effort medium` (high for money/tax diffs), DeepSeek `--provider fireworks --model accounts/fireworks/models/deepseek-v4p1-flash --effort max` (always max). The one-shot form stays `pi --provider openai-codex --model gpt-5.6-sol --thinking medium -p -t read -ne`; always pass both provider and model - a bare `--provider` leaves pi on its default model at max thinking. Use it when explicitly named, or when the diff's stakes warrant a second model family (money/tax paths, migrations, verification/archival gates, security). Never as a Claude-only pane fan-out; tmux/herdlet being available is NOT a reason to prefer it.
